# Data and schema

Moved out of [AGENTS.md](../../AGENTS.md), which keeps a short index of it. Paths are from the repository root.

`backend/prisma/schema.prisma`. Key models (not exhaustive):

| Model | Purpose |
|-------|---------|
| `User` | Google identity + mapped unix user. Holds `defaultAgentProvider` (string), `theme` (JSON — background mode and colour, shape in `src/theme/schema.ts`, `{}` = defaults), agent token records, usage rollups, `role`/`adminSource` (admin authorization), `lastSeenAt` (bumped by the auth gates at most once per 5 min). |
| `Project` | Name, working dir, `agentProvider` (string keyed into the provider registry, no longer an enum), Slack channel id, archived flag, owner, `pinned` flag and `lastActiveAt` timestamp (drive project-list ordering: pinned first, then recent activity), and `instanceId` (which box hosts the project). |
| `Instance` | A termag-running host ("box"). Tracks provisioning state, AWS identifiers, and the owning unix user. It also holds the agent's host sample (`diskUsedPct`, `memUsedPct`, `load1`, `keptCheckouts`, `hostSampledAt`) from its hello and the `host-sample` RPC every five minutes (`services/hostSamples.ts`), shown on Fleet and behind the `box_pressure` signal. `readyAt` holds the first agent connect, so `readyAt - createdAt` is that box's cold-provisioning time. `cleanedUpAt` is set only when a terminated ec2 box's AWS teardown fully finished; the provisioning sweep re-runs teardown for terminated rows without it (`docs/box-provisioning.md`). `parentInstanceId` is the box whose own credentials created this one through the CLI (null otherwise): that box may terminate it (an ask's box). Populated by `boxProvisioner` and the `/termag/api/instances` routes. |
| `Workstream` | A named line of work inside a project, backed by a git worktree. Every project has a `main` workstream auto-created on project creation; additional workstreams are managed through `backend/src/routes/workstreams.ts`. Non-main workstreams carry their own `slackChannelId` (`#proj-<user>-<project>-<workstream>`, auto-created and archived with the workstream); `main` uses `Project.slackChannelId`. Archiving a project deletes every workflow but keeps the workstream rows; un-archiving it on the same box gives each live workstream whose checkout still has a commit its agent back, resumed (`services/workstreamAgent.ts`), and a workstream left without one offers **Start agent…** (the switch-agent route). `sessionTitle` is Claude's own title for the workstream's chat session, written by the chat relay from a turn-end and led with in the simple UI's sidebar (`simple-ui-session-titles-enabled`). |
| `Automation` | One per project of kind `automation` (`projectId` unique): cron `schedule` + `timezone`, `prompt`, `tier` (`full`/`read`), `enabled`, `prOnChange`, `wakeBox`, `maxRunMinutes`, `keepRuns`, `spaceName` (phase 2), `pausedReason` + `consecutiveFailures`, and the scheduler's cursors `nextRunAt` / `lastOccurrence`. |
| `AutomationRun` | One occurrence: `trigger` (`schedule`/`manual`), `scheduledFor` (the minute), `state` (`pending`/`running`/`done`/`blocked`/`needs_input`/`failed`/`skipped`) with a one-word `reason`, the run's `workstreamId` (half of its chat key; set null when the worktree goes, `retiredAt`), `chatSessionId`, `summary`, `branch`, `prUrl`, cost and tokens. Unique on `(automationId, scheduledFor, trigger)` so two orchestrator processes start one run per occurrence. |
| `ProjectShare` | Collaborator grants on a project — `(projectId, userId)` with role. Backs the sharing routes; lets a non-owner reach the owner's tmux sessions through their own agent. |
| `ClaudeRunnerSession` | One row per **run** of a Claude Code cloud session on a box (one order each): owner, box, slot, `startedAt`, the end the box reports through `POST /api/claude-runner/event` (`endedAt`, `exitStatus`, `exitReason`), and since the Anthropic `sessionId` that groups runs into sessions, the `clientPlatform` from the box's `started` report, and the owner-only `title` (first prompt's first line, copied to a new run of the same session). It also holds the token usage the session posts about itself (`inputTokens` … `usageAt`, `model`), read by every token report as provider `claude-cloud` through `services/admin/tokenSource.ts`; the usage scanner never sees these sessions. |
| `ClaudeSessionEvent` | Append-only log of what happened to a cloud session, keyed by `sessionId`: every spawn outcome (`queued` with the refusal reason, `placed`, `already-running`, `agent-failed`), the box's `started` and `ended`, the reconciler's `lost`, an `end-requested` from the UI. `detail` never holds an email, a token or prompt text. Swept after 30 days; run rows after 90 (`services/claudeSessions.ts`). |
| `AgentToken` | Bearer token for a per-user agent connection. Issued from the UI sidebar. Carries `instanceId` so a token is scoped to a specific box, plus `scope` (`agent` default, `admin` for the admin surface) and an optional `expiresAt`. `/ws/agent`, the agent-facing REST routes and `/api/cli/v1`'s box credential accept only `agent`; `requireAdmin` accepts only `admin`. The CLI and `termag tui` sign in with `cli_sessions` (`tmcli_`), not this table. |
| `ChatActiveTarget` | What a Slack or Discord user's `/t` drives outside a project channel (`/t switch`, `/t attach`, the Home tab's Attach), keyed `(platform, chatUserId)` — the chat id, not a termag user, since the bot's operators may have none. Write-through copy of the map in `backend/src/slack/activeTargets.ts`; each chat bot reads it back when it connects on the lease holder, keeping whichever of row and memory is newer, and retrying every 30 s after a failed load. A first `/t`'s fallback project is a guess: kept in memory only, never written, replaced by any row. Cascades with its project; archived projects' rows are skipped on load. |
| `SessionStatus` | Write-through copy of the live in-memory status map (`services/statusPersistence.ts`): one row per `instanceKey+session` — status, meta, open `working` span. Restarts re-read it instead of showing every pill as `not_running`, and re-bank spans whose auto-idle deadline passed while down. Rows are pruned after 24 h untouched; there is no append-only event log (the old `StatusEvent` description was stale — the WebSocket push reads the live map). Status writes also bump `Project.lastActiveAt`. |
| `WorkTimeEntry` | Per-day, per-project, per-provider working-time rollup, banked by in-memory transition timers — agent spans in `services/status.ts` (bank on `working`→other transitions, 5-min auto-idle safety net, restart hydration via `session_statuses`), human typing time in `services/humanActivity.ts` (browser heartbeats while typing, 3-min decay). Upsert-increment keyed `(username, project, provider, date, instanceId)`. Powers `/termag/api/worktime` and the two-tube thermometer. |
| `UsageEvent` | Per-call API usage (tokens, cost) for the dashboard. Provider-specific scanners populate this (Codex JSONL, Claude logs, vibe `~/.vibe/logs/session/meta.json`). |
| `ProjectVisit` | Per-user context-switch log: when the UI focus moves between projects. Feeds the visits section of the UsageMini overlay via `/termag/api/visits`. |
| `WarpSample` | Per-minute rollups of the hyperspace-speed signal. Produced by `warpSampler` and exposed via `/termag/api/warp` for the flow-speed sections of UsageMini. |
| `AgentThread`, `AgentThreadPr`, `AgentMessage`, `AgentBundle` | Agent-to-agent asks: the thread (origin user, target project + workstream, Claude session id, base commit, repo, branch, PR, hop count), one row per PR the thread opened (`AgentThreadPr`: key, branch, number, URL), one row per ask (sender, sender box, status, hop, byte counts, publish outcome, whether a poll got the reply; never the reply, and the prompt only in `queuedPrompt` while an ask to the asker's parked box waits for it to connect, at most 15 minutes, or an ask to a project still cloning waits for the clone, at most 30), and the commits' bundle until published or 1 h old. Reply text is never stored: it reaches the waiting poll through Postgres `NOTIFY` (`services/askReplyBus.ts`) and is dropped if nobody waits. |
| `AdminAuditLog` | Every admin REST request and MCP tool call: actor, token if any, surface, action, args summary, outcome. Never pruned automatically. |
| `session` | `connect-pg-simple`'s session store. Declared in `schema.prisma` as model `Session` (`@@map("session")`) ONLY so `prisma db push` creates/keeps it under the migration DB user; the app never reads or writes it through Prisma. |

`prisma migrate dev` is fine here (this is an interactive box); on non-interactive deploy targets prefer `db push`.

**Schema changes are expand, then contract.** During an overlapping deploy the old and new orchestrator share the database, and the new one syncs with `DB_PUSH_MODE=additive`, which skips drops. So add first (nullable or defaulted; write both shapes, read the new one with a fallback), and drop the old shape only in a later release, by hand. A rename, a type change old code can't read, or a `NOT NULL` column without a default breaks the old process mid-deploy.
