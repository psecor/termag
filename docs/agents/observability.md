# Observability and maintenance

Moved out of [AGENTS.md](../../AGENTS.md), which keeps a short index of it. Paths are from the repository root.

- Orchestrator logs outlive the host when `termag-otelcol.service` ships them to a telemetry backend (`OBSERVABILITY_OTLP_ENDPOINT`, `OBSERVABILITY_PROJECT`). Filter on `service.name = termag-orchestrator` and `host.id` (the instance ID) or `host.image.id` (the AMI).
- `journalctl -u termag -f` — main server.
- `journalctl --user -u termag-agent -f` — per-user agent (run as the user).
- `tail -f /var/log/apache2/error.log` — proxy + WebSocket upgrade errors.
- Status events live in Postgres (`StatusEvent`) — usable for ad-hoc queries about agent activity.
- **Product events** (`backend/src/services/productEvents.ts`, `frontend/src/observability.ts`) are log records in the same project with `event.name` set, plus the `termag.product.events` counter by name; every one carries `context.contextKeys.user` (the user id) and, with a box, `context.contextKeys.box`, so they join browser sessions and agent telemetry on the same keys. Metadata only (enums, ids, counts, seconds; never a prompt, pane text, a brief, an email or a key). The vocabulary, with the `termag.*` attributes each carries: `project.created` {provider, repoSource: empty|github|template, boxKind: box|host, warmClaimed, spawned} · `box.provisioned` {boxKind, warmClaimed, provisioning: orchestrator|manual|external, child, claimMs} · `agent.session.started` {provider, kind: interactive, resume, spawned, clone} · `agent.session.ended` {provider, kind, lastStatus} · `agent.status.changed` {status, previousStatus, waitingReason, previousStatusSeconds (how long the previous status lasted, from the entry's `statusSince`; `updatedAt` is bumped by every write), provider} · `workstream.created` {provider, fromPr, spawned} · `share.invited` {invitee (a user id)} · `cloud.session.queued` / `.placed` {provider, kind: cloud, code} · `cloud.session.started` {clientPlatform, slot} · `cloud.session.ended` {durationSec, exitStatus, exitReason, slot}; from the browser (`recordProductEvent`, `termag.surface=browser`): `welcome.viewed`, `sshkey.added` {keyType, boxesUpdated}, `first.prompt` {pane: terminal|mobile; the agent pane only, by its `-agent` suffix (`isAgentPaneSession`) on the desktop and the pane role on mobile, a keyed Enter, once per page load}. Backend events go through the global OTel API, so they are a no-op wherever `services/otel.ts` has nowhere to send (dev, tests, the e2e stack); the browser's go through the Observability plugin's `LDObserve.recordLog` and are a no-op while the plugins are off. Add an event to `PRODUCT_EVENTS` and to this list in the same PR. Not yet wired: `agent.session.started` for Codex bridge launches and chat-runner sessions, `box.provisioned` for the ready transition (the agent's hello), and pi's resource lacks `termag.project`/`termag.workstream` (Codex's carries them: the agent telemetry resource gotcha in [gotchas.md](gotchas.md)).
- Per-request debug lines (`[STATUS] Push …`, `[STATUS] POST session=…`, `[GH-AUTHZ] … allowed`) print only with `TERMAG_DEBUG=STATUS,GH-AUTHZ` (or `all`) in the backend's environment (`services/debugLog.ts`); the collector's `filter/noise` drops the same lines from any journal, so switching them on does not re-flood the project.
- The agent process must be restarted whenever `agent/agent.js` changes (no hot reload). On a box, the orchestrator does that when it is safe (`deploy/termag-box-update`, started over the agent's `box-update` RPC once the `box-auto-update-enabled` flag is on for the box's owner and the box is behind the current image); a developer's checkout on a branch is left alone.
